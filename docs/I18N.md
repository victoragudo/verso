# Admin translations

The admin, the login screens, the installer and the public site are translated into 15 languages. The admin follows each user's language; the public site follows the site language (`site.locale`).

| Code | Language | Direction |
|---|---|---|
| `en` | English (source) | ltr |
| `es` | Español | ltr |
| `zh-Hans` | 简体中文 | ltr |
| `hi` | हिन्दी | ltr |
| `ar` | العربية | rtl |
| `pt-BR` | Português (Brasil) | ltr |
| `bn` | বাংলা | ltr |
| `ru` | Русский | ltr |
| `ja` | 日本語 | ltr |

`VERSO_ADMIN_LOCALES` limits the list (comma separated codes). The terms each translation uses are in [I18N-GLOSSARY.md](I18N-GLOSSARY.md).

## Which language is used

- Signed in: the user's choice (`users.admin_locale`), set in the user menu (Language) or on Settings > Profile. Without a choice the admin follows the site language when the admin has a translation for it, else English.
- Login, password and install screens: the language picked there (kept in the session), else the browser language (`Accept-Language`), else the site language. A language picked on the login screen becomes the user's choice at sign in when the user has none.
- Mail and notifications to a user use that user's admin language (`User::preferredLocale()`).
- `ApplyAdminLocale` sets the language on admin, account, login and install paths. Public pages keep `ApplySiteLocale`.
- `<html lang dir>` follows the admin language; Arabic gets `dir="rtl"`.

## Files

- Core strings: `lang/<code>.json`. Keys are the English text, so a missing translation shows English. `lang/en.json` is the catalog written by `php artisan verso:lang-extract`.
- Laravel messages (validation, auth, passwords, pagination): `lang/<code>/*.php`, from Laravel Lang (MIT).
- Plugins and themes: `<plugin or theme>/lang/<code>.json`, with keys without a prefix. Verso adds the `<slug>::` prefix when it loads them, so `plugins/shop/lang/es.json` with `{"Orders": "Pedidos"}` answers `shop::Orders`.
- The browser gets one JSON bundle per language with the core strings plus the files of enabled plugins and the active theme (and its parents): `GET /i18n/<code>/<version>.json`. The version is a hash of the files, so the URL changes when a translation changes and browsers can keep it for a year. The page preloads it, and the app waits for it before the first render. English needs no bundle.

## Public site

- `ApplySiteLocale` sets the site language (`site.locale`, Settings > General) on every web request. `ApplyAdminLocale` runs after it and switches only admin, account, login and install paths, so public pages, form posts and comment posts stay in the site language, also for signed in admins. The admin bar on public pages uses the admin's language (`AdminBar` renders it with `withLocale()`).
- Themes print `<html lang dir>` from `$site['locale']` and `$site['dir']`: Arabic gets `dir="rtl"`. Theme CSS uses logical properties so the layout flips.
- Core public views (comments, menus), site blocks (navigation, search, color scheme toggle, social links) and dynamic blocks use core keys: `__('Search')`. Block fields with an English default (like the search button text) show the translated default until someone changes the text.
- Plugin public views use their prefix: `__('shop::Your cart is empty.')`, `__('forms::Send')`.
- `$contentType->pluralLabel` and `$taxonomy->label` in theme views are the translated labels (`ContentLabels::translatedType()` and `translatedTaxonomy()`).
- Dates: `SiteTime::date($date)` prints a long date in the site time zone and language (Carbon `isoFormat('LL')`).
- Sample content of Easy mode and the default texts of forms (thank you message, button) are content: people edit them. Untouched form defaults show in the site language.

## Themes

- A theme keeps its strings in `themes/<slug>/lang/<code>.json`. `NamespacedJsonLoader` loads them with the `<slug>::` prefix for the active theme and its parents.
- Labels in `theme.json` (page template labels, setting labels, part variants, style tokens, patterns) are translated by `Theme\Support\ThemeText`. It tries `<slug>::<label>` for the theme, then its parents, then the core key.
- Theme views use `__('<slug>::Text')` for every text a visitor reads or hears, `Translate::icu('<slug>::{count, plural, ...}')` for plurals and `{!! __('<slug>::Go to the <a href=":url">home page</a>.', ['url' => e($url)]) !!}` for links inside a sentence. `verso:lang-extract` reads `themes/*/views` and writes the keys to the theme's `lang/en.json`.
- How to build and translate a theme: [THEME-GUIDE.md](THEME-GUIDE.md#translations-and-right-to-left-languages).

## Writing translatable code

### React (TypeScript)

```tsx
import { formatDateTime, formatNumber, msg, t, Trans } from '@/lib/i18n';

<Button>{t('Publish')}</Button>
<Input placeholder={t('Search posts')} aria-label={t('Search posts')} />
toast.success(t('Saved “{title}”.', { title }));
<p>{t('{count, plural, =0 {No comments} one {# comment} other {# comments}}', { count })}</p>
```

- Every text people read or hear goes through `t()`: JSX text, `aria-label`, `title`, `placeholder`, `alt`, toasts, confirm texts, empty states, errors, labels of options and tabs.
- Write the full sentence with ICU arguments: `t('Moved {title} to the trash.', { title })`. Never join pieces of a sentence, and never build plurals with `count === 1 ? ... : ...`; use `{count, plural, one {...} other {...}}`. `#` is the formatted number.
- Use `select` for words that change with a value: `{status, select, draft {Draft} published {Published} other {Unknown}}`.
- Module level constants run before the strings load. Mark them with `msg('Drafts')` and call `t(label)` when rendering.
- Links or bold text inside a sentence: `<Trans text={t('Read the <link>guide</link>.')} components={{ link: (text) => <a href="...">{text}</a> }} />`.
- Numbers, money, dates, relative times, lists and file sizes: `formatNumber`, `formatCurrency`, `formatPercent`, `formatCompact`, `formatDateTime`, `formatRelativeTime`, `formatList`, `formatBytes`, `languageName` from `@/lib/i18n`, or `useSiteDates()` for dates in the site time zone. Never call `toLocaleString()` or `Intl.*` without the admin locale.
- Text that comes from the server (nav labels, settings labels, flash messages, validation errors) is already translated. Do not pass it to `t()` again.
- Do not translate what people typed (titles, names, content), slugs, URLs, code, file types or brand names.
- Admin pages and components of a bundled plugin (`resources/js/pages/admin/plugins/<slug>`, `resources/js/components/verso/<slug>`, `plugins/<slug>/resources/js`) use keys with the plugin prefix for their own text: `t('shop::Orders')`. Common words of the admin (Save, Cancel, Delete, Search, Status, Name) may use the core key: `t('Save')`.
- Layout: use logical utilities (`ms-`, `me-`, `ps-`, `pe-`, `start-`, `end-`, `border-s`, `text-start`, `rounded-e`). Leave room for longer text (German and Russian are often 30% longer): no fixed widths on buttons and labels, let text wrap.

### PHP

```php
Inertia::flash('toast', ['type' => 'success', 'message' => __('Settings saved.')]);
__('Saved “:title”.', ['title' => $entry->title]);
__('shop::Order :number was paid.', ['number' => $order->number]);
Translate::icu('{count, plural, one {# post moved} other {# posts moved}} to the trash.', ['count' => $count]);
```

- Flash messages, validation messages, exceptions shown to people, notifications and mail sent to admins use `__()` (`:name` placeholders) or `Translate::icu()` (ICU plurals).
- Labels registered at boot (nav items, dashboard stats, System settings, content types, capabilities, manifest labels) are kept in English and translated when they are sent to the browser: `Translate::text($label, plugin: $slug)` tries `<slug>::<label>` first, then the core key.
- Plugin code uses its prefix: `__('forms::Message sent.')`.

### Tools

- `php artisan verso:lang-extract` writes the English catalogs from the code (t(), msg(), __() in PHP, Blade and theme views, registry labels, manifests) and lists missing and unused keys per language. `--missing` lists them, `--prune` removes unused keys, `--check` fails when something is out of date (CI).
- Registry labels are found by their key or named argument (`label`, `description`, `title`, `summary`, `help`, `message`, `action`...), and lists by `keywords` and `steps`. PHP between `// i18n-ignore-start` and `// i18n-ignore-end` lines is skipped for labels: use it for sample site content, like the pages of Easy mode starter sites, which is written in the site language.
- `node scripts/i18n/hardcoded-strings.mjs [paths]` lists English text in admin TSX that is not in `t()` or `msg()`. `scripts/i18n/hardcoded-allowlist.json` lists brand names and files to skip. The Vitest test `resources/js/tests/i18n/hardcoded-strings.test.ts` runs it.
- `tests/Feature/I18n/ThemeViewStringsTest.php` fails when a theme view, a plugin theme view or a core public view prints English text outside `__()`: text between tags, `aria-label`, `placeholder`, `title`, `alt` and `label` attributes, and sentences in PHP strings like `{{ $empty ?? 'Nothing here.' }}`. Attribute values without lowercase letters, like the country code `ES`, are allowed.
- `tests/Feature/I18n/LangFilesTest.php` checks that every language file has every key, no empty or English-only placeholders, and the same ICU arguments and `:placeholders` as English.
- The same test fails when a translation is a copy of the English text. When English is right in a language (brand names, units, code, loan words like "Blog"), add the key to `tests/Feature/I18n/same-as-english.json` under its catalog folder, with `"*"` for every language or a list of language codes. Texts without words, like `{count} / {total}`, are always allowed.
